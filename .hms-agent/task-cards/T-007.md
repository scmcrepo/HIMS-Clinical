## Implementation notes

- bookAppointment requires a concrete slotId — the agent cannot book from natural language in one hop. check_slot_availability (delegating to AppointmentSchedulingService.getSlotAvailability) must come first and its response must give the agent everything it needs to choose: slotId, start, end, remaining capacity.
- Map AppointmentSchedulingService's BusinessRuleViolationException cases to specific error codes: SLOT_FULL, SLOT_NOT_FOUND, PATIENT_NOT_FOUND, DUPLICATE_BOOKING. The service throws these at lines ~90, ~99, ~106 — read them and map faithfully rather than guessing.
- PII CARE: BookAppointmentRequest carries tempPatientName, tempPatientPhone, tempPatientAge for walk-ins, and these are unencrypted on the existing path. The agent tool must not widen that exposure — do not log them, do not echo them in audit rows, and flag the pre-existing gap in the ledger as a note for a future work order rather than fixing it here.
- fetch_billing_ledger delegates to the existing billing service. Response contains financial PII — it is a legitimate tool response, but it must never reach a log line.
- book_slot is a write tool but idempotency lands in T-008. Until then, document clearly that retries can double-book; do not ship this to a live agent before T-008.
