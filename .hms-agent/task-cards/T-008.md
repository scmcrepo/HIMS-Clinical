## Implementation notes

- X-Idempotency-Key is mandatory on book_slot; a missing key is a 400 with code IDEMPOTENCY_KEY_REQUIRED. LLM agents retry, and a silent double-booking is the kind of failure a hospital notices in the waiting room.
- Replay returns the stored response with 200 and header Idempotency-Replayed: true.
- The stored response body may contain PII, so the column uses EncryptedStringConverter. TTL 24 hours.
- Concurrency: two simultaneous requests with the same key must produce one appointment. Use a unique constraint on (tenant_id, key_hash) and treat the constraint violation as the replay path rather than relying on a read-then-write check.
- LANDMINE: the purge job is @Scheduled, so it runs on a thread with no tenant context. It must either operate tenant-agnostically at the SQL level with an explicit predicate, or set TenantContext per tenant explicitly and clear in finally — see BulkImportAsyncService for the pattern.
- hms_agent_idempotency_replays_total{tool} metric.
