## Goal

A bearer token authenticates a machine client into an HmsUserDetails carrying its tenant, branch and scopes — so tenant filters, RBAC and audit apply unchanged — on a stateless chain that never creates a session.

## Implementation notes

- THE KEY INSIGHT from WO-001 section 3b: build an HmsUserDetails with tenantId, branchId, featureKeys = token scopes, roleNames = {AGENT}. TenantResolutionFilter already reads the principal from SecurityContext and enables the Hibernate filters, and HmsPermissionEvaluator falls back to matching the raw feature key against getAuthorities(), which HmsUserDetails populates from featureKeys. Nothing in the 176 existing controllers needs to change.
- Two filter chains. @Order(1) securityMatcher(/agent/**) with SessionCreationPolicy.STATELESS, AgentTokenAuthenticationFilter added before UsernamePasswordAuthenticationFilter, TenantResolutionFilter still after it. @Order(2) is the existing chain, untouched. Getting the order or matcher wrong makes agent requests fall through to form login — see the risk table.
- STATELESS is what dodges maximumSessions(1)/maxSessionsPreventsLogin(true), which is why session-cookie auth was rejected. Prove it with a test, because a regression here silently caps the agent at one process.
- last_used_at: do NOT write on every request — that is a DB write per tool call. Throttle to at most once per minute per token, or update asynchronously (with explicit tenant context on the worker thread, per the BulkImportAsyncService pattern).
- 401 responses must not leak whether the token is unknown, expired or revoked. One generic message; the specific reason goes to the log with a reason field.
- Constant-time comparison on the hash lookup path where practical.

## Definition of done

Card-specific:
- [ ] Valid token reaches a protected endpoint; invalid, expired, revoked and malformed tokens all get 401 and increment hms_agent_auth_failures_total{reason}.
- [ ] No Set-Cookie on any /agent response — asserted by test. No HttpSession created.
- [ ] Two concurrent requests with the same token both succeed, proving maximumSessions(1) does not apply.
- [ ] A token scoped only to AGENT_BED_READ receives 403 on a scheduling-write endpoint.
- [ ] Tenant isolation: a tenant A token receives 404/403 for tenant B resources. Testcontainers, asserting absence rather than filtered output.
- [ ] The existing browser login flow is completely unaffected — full existing test suite green.
- [ ] last_used_at updates at most once per minute per token under load.
